PROBLEM SOLVED
==============

✓ Issue: Some clients kept rotating the first photo instead of cycling
         through the entire photo library.

✓ Root Cause: photo_index and photo_served were read but never incremented,
              so the cookie never updated, preventing clients from tracking
              which photos had been served.

✓ Solution: Implemented Option 3 - Session Hash-Based Tracking with Cycling


IMPLEMENTATION OVERVIEW
========================

New System: Cycle-Based Photo Serving with Session Tracking
  
  Phase 1: Serve all same-day photos sequentially (no duplicates)
  Phase 2: Serve N random photos (N = cache.same_day_cycle config, default 100)
  Repeat forever

Each browser gets:
  • Unique session_id (UUID, persisted in cookie)
  • Server-side session tracking with MD5 hashes
  • Automatic phase transitions
  • 24-hour session expiration

HOW IT WORKS
============

Browser Request Flow:

  Request 1-5:   Session starts in "same_day" phase
                 ├─ Fetch same-day photo 1-5
                 ├─ Mark each as served (MD5 hash)
                 └─ ✓ Serve without duplication

  Request 6:     All same-day photos served
                 ├─ Trigger transition to "random" phase
                 ├─ Reset same_day tracking
                 └─ Serve first random photo (counter = 1)

  Request 7-106: Show 100 random photos
                 ├─ Increment random counter each time
                 ├─ At count 100, trigger transition back
                 └─ ✓ Exact quota enforcement

  Request 107:   Random quota reached (100)
                 ├─ Trigger transition to "same_day" phase
                 ├─ Reset tracking
                 └─ Back to same-day photos (cycle repeats)

  ... repeats forever with no duplicates within cycles


CONFIGURATION
=============

No new config files needed. Uses existing cache.same_day_cycle:

  cache:
    limit_enabled: false
    limit: 2000
    same_day_cycle: 100     # ← Adjust this for cycle ratio

To change photo cycling:
  • Increase same_day_cycle → More random photos between same-day cycles
  • Decrease same_day_cycle → Same-day photos appear more frequently
